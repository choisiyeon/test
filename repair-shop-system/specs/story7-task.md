| 항목 | 내용 |
| --- | --- |
| 에픽 | E2 고객관리 |

---

## 1. 요약

- 삭제는 '개인정보 익명화' 방식: 이름·전화번호·메모를 지우고 고객 행은 "삭제된 고객"으로 남김
- 접수·결제 기록은 매출 집계에 필요하므로 유지(고객 식별 정보만 제거)
- 진행 중인 접수(접수·작업중·완료 미출고)가 있으면 삭제 불가
- 관리자만 가능, 삭제 사유와 처리자 기록

※ 매출 기록 보관 의무와 개인정보 파기 기준의 관계는 개인정보 보호법 등 관련 법령 기준을 전문가에게 확인 필요

---

## 2. 인수 조건

1. 관리자가 고객 상세에서 [삭제]를 누르고 사유를 입력해 확인하면 이름·전화번호·메모가 지워지고 "삭제된 고객"으로 표시된다.
2. 삭제된 고객의 지난 접수·결제 기록은 매출 집계에 그대로 포함된다.
3. 진행 중인 접수가 있는 고객은 "진행 중인 접수 n건이 있어 삭제할 수 없습니다"가 표시되고 삭제되지 않는다.
4. 직원 화면에는 [삭제] 버튼이 없고, API로 요청해도 거부된다.
5. 삭제된 고객은 고객 검색과 접수 화면 고객 검색에 나타나지 않는다.
6. 삭제는 되돌릴 수 없음을 확인 창에서 알린다.

---

## 3. 데이터 모델 변경

```prisma
model Customer {
  // ...기존 항목
  deletedAt     DateTime?
  deletedById   String?
  deleteReason  String?
}
```

- 삭제 시 처리: `name = '삭제된 고객'`, `phone = ''`, `phoneLast4 = ''`, `memo = null`, `deletedAt = now()`
- CustomerChangeLog(US-05)의 해당 고객 이력도 before/after 값 삭제
- 사진(US-03)은 해당 고객 접수의 사진도 함께 삭제할지 확인 필요(현재 설계: 함께 삭제 표시)

---

## 4. API 설계

| 메서드 | 경로 | 설명 | 권한 |
| --- | --- | --- | --- |
| GET | `/api/customers/:id/delete-check` | 삭제 가능 여부, 진행 중 접수 건수 | 관리자 |
| DELETE | `/api/customers/:id` | 익명화 삭제 | 관리자 |

```json
// DELETE 요청
{ "reason": "고객 요청" }

// 응답 200
{ "id": "ck...", "deleted": true }

// 응답 409
{ "error": "HAS_ACTIVE_ORDERS", "count": 2 }
```

### 처리 순서 (하나의 트랜잭션)

1. 관리자 확인 → 사유 필수 확인
2. 진행 중 접수(RECEIVED, IN_PROGRESS, DONE) 건수 확인 → 1건 이상이면 409
3. 고객 정보 익명화, 변경 이력 값 삭제
4. 관련 사진 삭제 표시(실제 파일 삭제는 정기 작업에서 처리)
5. 삭제 기록(AuditLog: 대상, 처리자, 일시, 사유) 저장

```prisma
model AuditLog {               // 관리자 주요 작업 기록(이후 스토리 공용)
  id        String   @id @default(cuid())
  action    String             // CUSTOMER_DELETE, PAYMENT_CANCEL 등
  targetId  String
  reason    String?
  actorId   String
  createdAt DateTime @default(now())
}
```

## 5. 화면

- 고객 상세(관리자만) [삭제] 버튼 → 확인 창: "이름·전화번호·메모가 삭제되며 되돌릴 수 없습니다. 접수·결제 기록은 매출 집계를 위해 남습니다." + 사유 입력 + [삭제]
- 고객 검색 기본 조건에 `deletedAt = null` 추가
