# [US-08] 미수령 의류 조회 — 개발 Task 설계서

| 항목 | 내용 |
| --- | --- |
| 에픽 | E2 고객관리 |
| 스토리 | 직원으로서 수선이 끝났는데 찾아가지 않은 의류 목록을 보고 싶다. 장기 미수령 의류를 파악해 고객에게 다시 연락하고 보관 공간을 관리하기 위해서다. |
| 우선순위 / 릴리스 | 필수 / 1차 |
| 관련 기능 | F-11 미수령 관리 |
| 관련 화면 / 데이터 | S-05 고객 관리(미수령 탭), S-02 대시보드 / D-02 접수, D-08 매장 설정 |
| 선행 작업 | US-02(doneAt), US-04 |
| 작성일 | 2026-11-25 |

---

## 1. 요약

- 미수령 = 상태 '완료'이고 완료 일시(doneAt) 이후 기준 일수가 지난 건
- 기준 일수는 관리자가 설정 화면에서 지정(매장 설정 값, 기본값은 결정 필요)
- 목록에서 경과 일수, 알림 발송 횟수, 마지막 발송일 확인 → 재안내(US-11)로 연결

---

## 2. 인수 조건

1. 미수령 목록에는 '완료' 상태이며 완료 후 기준 일수가 지난 건만 경과 일수가 긴 순으로 표시된다.
2. 각 건에 고객명(가림), 품목, 완료일, 경과 일수, 알림 발송 횟수, 마지막 발송일이 표시된다.
3. 기준 일수를 변경하면 목록이 새 기준으로 다시 계산된다.
4. 대시보드에 미수령 건수가 표시되고, 누르면 미수령 목록으로 이동한다.
5. 기준 일수가 설정되지 않았으면 "설정에서 미수령 기준 일수를 지정하세요" 안내가 표시된다.

---

## 3. 데이터 모델 변경

```prisma
model StoreSetting {           // D-08 매장 설정(키-값, 이후 스토리 공용)
  key       String   @id       // 예: UNCLAIMED_DAYS, STORE_NAME
  value     String
  updatedById String?
  updatedAt DateTime @updatedAt
}
```

- 알림 발송 횟수·마지막 발송일은 US-09 NotificationLog에서 집계(US-09 구현 전에는 '-' 표시)

## 4. API 설계

| 메서드 | 경로 | 설명 | 권한 |
| --- | --- | --- | --- |
| GET | `/api/orders/unclaimed?page=` | 미수령 목록 | 관리자·직원 |
| GET | `/api/settings/UNCLAIMED_DAYS` | 기준 일수 조회 | 관리자·직원 |
| PUT | `/api/settings/UNCLAIMED_DAYS` | 기준 일수 변경 | 관리자 |

```json
// GET /api/orders/unclaimed
{ "thresholdDays": null, "items": [], "message": "SETTING_REQUIRED" }   // 미설정 시

{ "thresholdDays": 14, "items": [
  { "orderNo": "20261010-004", "customerName": "이*희", "itemTypeName": "코트",
    "doneAt": "2026-10-15", "elapsedDays": 41, "notifyCount": 2, "lastNotifiedAt": "2026-11-01" } ] }
```

※ 응답 예시의 14일은 형식 예시이며 실제 기준은 매장에서 결정

- 경과 일수 = KST 오늘 날짜 − doneAt 날짜
