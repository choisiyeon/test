---

## 1. 요약

- US-01에서 만든 '접수 화면 내 신규 고객 등록'을 고객 관리 화면으로 확장하고 수정 기능 추가
- 같은 전화번호 고객이 이미 있으면 등록 전에 안내(중복 고객 방지, 가족 공용 번호를 고려해 차단하지는 않음)
- 수정 시 변경 이력 기록(누가·언제·무엇을)

---

## 2. 인수 조건

1. 고객 관리 화면에서 이름·전화번호를 입력하고 저장하면 고객이 등록된다.
2. 이미 등록된 전화번호를 입력하면 "같은 번호의 고객이 있습니다" 안내와 기존 고객 목록이 표시되고, [그래도 등록] 또는 [기존 고객 선택]을 고를 수 있다.
3. 전화번호 형식이 맞지 않으면 저장되지 않고 안내가 표시된다.
4. 고객 상세에서 이름·전화번호·메모를 수정하면 반영되고 변경 이력이 남는다.
5. 전화번호는 하이픈 유무와 관계없이 입력 가능하며 숫자만 저장된다.

---

## 3. 데이터 모델 변경

```prisma
model CustomerChangeLog {
  id          String   @id @default(cuid())
  customerId  String
  field       String           // name | phone | memo
  beforeValue String?          // 전화번호는 가림 처리해 저장
  afterValue  String?
  changedById String
  changedAt   DateTime @default(now())
  @@index([customerId])
}
```

## 4. API 설계

| 메서드 | 경로 | 설명 | 권한 |
| --- | --- | --- | --- |
| POST | `/api/customers` | 고객 등록(US-01 API 확장: 중복 확인 응답 추가) | 관리자·직원 |
| GET | `/api/customers/check-phone?phone=` | 같은 번호 고객 확인 | 관리자·직원 |
| PATCH | `/api/customers/:id` | 고객 정보 수정 | 관리자·직원 |

```json
// POST 요청
{ "name": "홍길동", "phone": "010-1234-5678", "memo": "단추 여분 보관", "confirmDuplicate": false }

// 응답 409 (같은 번호 존재, confirmDuplicate=false)
{ "error": "DUPLICATE_PHONE", "candidates": [{ "id": "ck...", "name": "홍*동", "lastOrderAt": "2026-10-02" }] }

// 응답 201
{ "id": "ck...", "name": "홍길동" }
```

- 전화번호 정규화: 숫자 외 문자 제거 → `^01[016789]\d{7,8}$` 검사(휴대전화 기준, 일반전화 허용 여부 확인 필요)
