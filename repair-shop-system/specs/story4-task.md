---

## 1. 요약

- 접수 목록 화면의 검색·정렬·페이지 처리 전체를 본 스토리에서 담당
- US-02 설계서의 목록 API(`GET /api/orders`)와 목록 화면 항목은 본 설계서 기준으로 구현(중복 개발 방지)
- 기한 경과 = 상태가 '접수' 또는 '작업중'이면서 완료 예정일이 오늘보다 이전인 건

---

## 2. 인수 조건

1. 목록을 열면 최근 접수 순으로 표시된다.
2. 상태·접수 기간·고객명·접수번호 중 하나 이상으로 검색하면 조건에 맞는 건만 표시된다.
3. [기한 경과만] 선택 시 기한이 지난 미완료 건만 표시된다.
4. 기한 경과 건은 목록에서 ⚠ 표시와 붉은 글씨로 구분된다.
5. 검색 결과가 없으면 "검색 결과가 없습니다"가 표시된다.
6. 목록에서 고객명은 가운데 글자, 전화번호는 가운데 4자리가 가려져 표시된다.

- 성능용 인덱스 추가: `@@index([status, dueDate])`, `@@index([createdAt])`

## 4. API 설계

| 메서드 | 경로 | 설명 | 권한 |
| --- | --- | --- | --- |
| GET | `/api/orders` | 접수 목록 검색 | 관리자·직원 |

### 검색 조건

| 파라미터 | 형식 | 설명 |
| --- | --- | --- |
| status | `RECEIVED,IN_PROGRESS` (쉼표 구분) | 상태 복수 선택 |
| from / to | `YYYY-MM-DD` | 접수일 기간 |
| q | 문자열 | 고객명 일부 또는 접수번호(`YYYYMMDD-NNN`) 또는 전화번호 뒤 4자리 |
| overdue | `true` | 기한 경과만 |
| sort | `createdAt_desc`(기본), `dueDate_asc` | 정렬 |
| page / size | 숫자 | 페이지 번호, 페이지당 건수(기본 20, 제안값) |

```json
// 응답 200
{
  "items": [
    { "id": "ck...", "orderNo": "20261120-003", "customerName": "김*수",
      "phoneMasked": "010-****-1234", "itemTypeName": "셔츠",
      "dueDate": "2026-11-22", "status": "IN_PROGRESS", "overdue": true }
  ],
  "page": 1, "size": 20, "total": 43
}
```

### 처리 규칙

- q 판별: `^\d{8}-\d{3,}$` → 접수번호 일치, `^\d{4}$` → 전화번호 끝 4자리, 그 외 → 고객명 부분 일치
- overdue 계산은 서버에서 한국 시간(KST) 오늘 0시 기준
- 가림 처리는 서버 응답 단계에서 수행(화면에서 가리지 않음 → 원본 전송 방지)

## 5. 화면 (S-04 접수 목록)

```
[상태 ☑접수 ☑작업중 ☐완료 ☐출고] [기간 2026-11-01 ~ 2026-11-30] [검색어      ] [☐기한 경과만] [검색]
정렬: (●)최근 접수순 ( )완료 예정일순                                   총 43건
┌──────────────┬──────┬──────┬──────────┬────────┬──────────┐
│ 접수번호      │ 고객  │ 품목  │ 완료예정일 │ 상태    │ 처리      │
│ 20261120-003 │ 김*수 │ 셔츠  │ 11-22 ⚠  │ 작업중  │[작업 완료]│
└──────────────┴──────┴──────┴──────────┴────────┴──────────┘
                     [< 이전] 1 2 3 [다음 >]
```

- 검색 조건은 주소(URL)에 저장 → 새로고침·뒤로가기 시 유지
- 행 클릭 시 접수 상세로 이동, [처리] 버튼은 US-02 상태 변경 호출
