## 3. 시나리오 상세 (Given-When-Then)

### AC-07-01 관리자의 익명화 삭제  `정상` `E2E·통합`

```gherkin
Scenario: 관리자의 익명화 삭제
  Given 관리자로 로그인되어 있다
    And 고객 X에게 진행 중인 접수가 없다
  When 고객 X 상세에서 [삭제]를 누르고 사유 "고객 요청"을 입력해 확인한다
  Then 고객 이름이 "삭제된 고객"으로 표시된다
    And 전화번호와 메모가 지워진다
    And 삭제 기록에 처리자, 일시, 사유가 남는다
```

### AC-07-02 삭제 후 매출 기록 유지  `정상` `통합`

```gherkin
Scenario: 삭제 후 매출 기록 유지
  Given 고객 X의 결제가 11월 매출에 포함되어 있다
  When 고객 X를 삭제한다
  Then 삭제 전후 11월 순매출 합계가 같다
```

### AC-07-03 진행 중 접수가 있으면 삭제 불가  `예외` `통합·E2E`

```gherkin
Scenario: 진행 중 접수가 있으면 삭제 불가
  Given 고객 Y에게 "작업중" 접수 1건이 있다
  When 관리자가 고객 Y 삭제를 시도한다
  Then "진행 중인 접수 1건이 있어 삭제할 수 없습니다"가 표시된다
    And 고객 정보가 그대로 유지된다
```

### AC-07-04 직원 삭제 차단  `권한` `E2E·통합`

```gherkin
Scenario: 직원 삭제 차단
  Given 직원으로 로그인되어 있다
  When 고객 상세 화면을 연다
  Then [삭제] 버튼이 보이지 않는다
  When 고객 삭제 API를 요청한다
  Then 403 응답이 반환된다
```

### AC-07-05 삭제 고객 검색 제외  `정상` `통합`

```gherkin
Scenario: 삭제 고객 검색 제외
  Given 고객 X가 삭제되었다
  When 고객 관리 화면과 접수 화면에서 고객 X의 이전 이름으로 검색한다
  Then 검색 결과에 나타나지 않는다
```

### AC-07-06 되돌릴 수 없음 안내  `정상` `E2E`

```gherkin
Scenario: 되돌릴 수 없음 안내
  Given 관리자가 [삭제]를 눌렀다
  When 확인 창이 열린다
  Then "되돌릴 수 없습니다"와 "접수·결제 기록은 매출 집계를 위해 남습니다" 문구가 표시된다
```

### AC-07-07 삭제 후 원문 잔존 없음  `보안` `통합`

```gherkin
Scenario: 삭제 후 원문 잔존 없음
  Given 고객 X의 전화번호를 수정한 이력이 있다
  When 고객 X를 삭제한다
  Then 고객 정보와 변경 이력 어디에도 고객 X의 전화번호 원문이 남아 있지 않다
```

### AC-07-08 사유 누락 거부  `입력 검증` `통합`

```gherkin
Scenario: 사유 누락 거부
  Given 관리자로 로그인되어 있다
  When 사유 없이 삭제 API를 요청한다
  Then 삭제되지 않고 사유 입력 안내가 반환된다
```
