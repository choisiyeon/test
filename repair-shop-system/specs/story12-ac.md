## 2. 테스트 전제·데이터

- 공통: 관리자 "owner", 직원 "staff01" 계정, 시험 시각은 한국 시간(KST) 기준으로 고정
- 접수 금액 8,000원

## 3. 시나리오 상세 (Given-When-Then)

### AC-12-01 선결제 접수  `정상` `통합·E2E`

```gherkin
Scenario: 선결제 접수
  Given 직원으로 로그인되어 수선 접수 화면을 열었다
  When [선결제]와 결제수단 "현금"을 선택하고 접수를 저장한다
  Then 접수와 함께 결제(선결제, 현금, 8000원)가 기록된다
```

### AC-12-02 미결제 건 결제 후 출고  `정상` `E2E`

```gherkin
Scenario: 미결제 건 결제 후 출고
  Given 접수 E가 "완료" 상태이며 미결제다
  When [출고]를 누르고 결제수단 "카드"를 선택해 [결제 후 출고]를 누른다
  Then 결제(후결제, 카드, 8000원)가 기록되고 상태가 "출고"로 바뀐다
```

### AC-12-03 결제 완료 건 바로 출고  `정상` `통합`

```gherkin
Scenario: 결제 완료 건 바로 출고
  Given 접수 F가 "완료" 상태이며 선결제되어 있다
  When [출고]를 누른다
  Then 추가 결제 없이 상태가 "출고"로 바뀐다
```

### AC-12-04 금액 변경 시 사유 필수  `입력 검증` `통합`

```gherkin
Scenario: 금액 변경 시 사유 필수
  Given 미결제 접수의 출고 팝업이다
  When 금액을 7000원으로 바꾸고 사유 없이 저장한다
  Then 저장되지 않고 사유 입력 안내가 표시된다
  When 사유 "단골 할인"을 입력해 저장한다
  Then 결제 금액 7000원과 사유가 기록된다
```

### AC-12-05 미결제 출고 차단 정책  `예외` `통합`

```gherkin
Scenario: 미결제 출고 차단 정책
  Given 미결제 출고 정책이 "차단"이다
  When 결제 없이 출고를 요청한다
  Then 출고가 거부되고 상태는 "완료"로 유지된다
```

### AC-12-06 미결제 출고 경고 후 허용 정책  `예외` `통합·E2E`

```gherkin
Scenario: 미결제 출고 경고 후 허용 정책
  Given 미결제 출고 정책이 "경고 후 허용"이다
  When 결제 없이 출고를 요청한다
  Then 경고 확인 창이 표시된다
  When 확인한다
  Then 상태가 "출고"로 바뀌고 "미결제 출고"로 표시된다
```

### AC-12-07 결제 내역 표시  `정상` `E2E`

```gherkin
Scenario: 결제 내역 표시
  Given 결제가 기록된 접수가 있다
  When 접수 상세를 연다
  Then 결제 일시, 결제수단, 금액, 처리자가 표시된다
```

### AC-12-08 결제·출고 동시 처리 보장  `예외` `통합`

```gherkin
Scenario: 결제·출고 동시 처리 보장
  Given 출고 처리 중 상태 변경 단계에서 오류가 발생하도록 설정했다
  When 결제 후 출고를 요청한다
  Then 결제도 기록되지 않는다(결제만 남는 경우 없음)
```

### AC-12-09 완료 상태가 아닌 건 출고 불가  `입력 검증` `통합`

```gherkin
Scenario: 완료 상태가 아닌 건 출고 불가
  Given 접수 상태가 "작업중"이다
  When 출고를 요청한다
  Then 거부되고 상태가 유지된다
```
