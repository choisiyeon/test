## 3. 시나리오 상세 (Given-When-Then)

### AC-19-01 품목 등록 후 접수 화면 반영  `정상` `E2E`

```gherkin
Scenario: 품목 등록 후 접수 화면 반영
  Given 관리자로 로그인되어 있다
  When 품목 "소매 줄임"을 기본 단가와 함께 등록한다
  Then 접수 화면 품목 목록에 "소매 줄임"이 표시된다
```

### AC-19-02 기본 단가 자동 입력  `정상` `E2E`

```gherkin
Scenario: 기본 단가 자동 입력
  Given 품목 "소매 줄임"에 기본 단가가 있다
  When 직원이 접수 화면에서 "소매 줄임"을 고른다
  Then 금액 칸에 기본 단가가 입력된다
```

### AC-19-03 품목명 중복 거부  `입력 검증` `통합`

```gherkin
Scenario: 품목명 중복 거부
  Given 품목 "바지 기장 줄임"이 있다
  When " 바지 기장 줄임 "(앞뒤 공백 포함)으로 등록한다
  Then 거부되고 중복 안내가 표시된다
```

### AC-19-04 사용 중지  `정상` `통합`

```gherkin
Scenario: 사용 중지
  Given 품목 "바지 기장 줄임"으로 접수된 건이 있다
  When 관리자가 해당 품목을 "사용 중지"한다
  Then 접수 화면 품목 목록에서 사라진다
    And 과거 접수와 품목별 매출 집계에는 그대로 남는다
```

### AC-19-05 순서 변경  `정상` `E2E`

```gherkin
Scenario: 순서 변경
  Given 품목 3개가 있다
  When 세 번째 품목을 맨 위로 옮긴다
  Then 접수 화면 목록에서도 맨 위에 표시된다
```

### AC-19-06 단가 변경 시 기존 접수 불변  `정상` `통합`

```gherkin
Scenario: 단가 변경 시 기존 접수 불변
  Given "바지 기장 줄임"으로 접수된 건의 금액이 저장되어 있다
  When 관리자가 해당 품목 기본 단가를 바꾼다
  Then 기존 접수 금액은 바뀌지 않는다
    And 단가 변경 기록이 남는다
```

### AC-19-07 직원 차단  `권한` `통합`

```gherkin
Scenario: 직원 차단
  Given 직원으로 로그인되어 있다
  When 품목 등록·수정 API를 요청한다
  Then 403 응답이 반환된다
```

### AC-19-08 단가 입력 검증  `입력 검증` `통합`

```gherkin
Scenario: 단가 입력 검증
  Given 관리자로 로그인되어 있다
  When 기본 단가를 음수로 저장한다
  Then 저장되지 않는다
  When 기본 단가를 비워 두고 저장한다
  Then 단가 미지정 품목으로 저장된다
```
