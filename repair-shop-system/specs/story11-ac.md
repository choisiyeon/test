## 3. 시나리오 상세 (Given-When-Then)

### AC-11-01 건별 재안내  `정상` `통합·E2E`

```gherkin
Scenario: 건별 재안내
  Given 직원으로 로그인되어 미수령 목록을 열었다
  When 한 건의 [재안내]를 누르고 확인한다
  Then 해당 고객에게 재안내가 발송된다
    And 알림 이력에 유형 "재안내"로 기록된다
```

### AC-11-02 선택 건 일괄 재안내  `정상` `통합·E2E`

```gherkin
Scenario: 선택 건 일괄 재안내
  Given 미수령 건 3건이 있다
  When 3건을 선택해 [선택 건 재안내]를 누른다
  Then 대상 2건은 발송되고, 최소 간격 미경과 1건은 건너뛴다
    And "성공 2건, 건너뜀 1건" 결과가 표시된다
```

### AC-11-03 최소 간격 미경과 시 버튼 비활성화  `예외` `E2E`

```gherkin
Scenario: 최소 간격 미경과 시 버튼 비활성화
  Given 마지막 발송 후 최소 간격이 지나지 않은 건이 있다
  When 미수령 목록을 연다
  Then 해당 건의 재안내 버튼이 비활성화되고 "n일 후 가능"이 표시된다
```

### AC-11-04 자동 재안내  `정상` `통합`

```gherkin
Scenario: 자동 재안내
  Given 자동 재안내가 켜져 있다
  When 일일 자동 재안내 작업이 실행된다
  Then 대상 조건을 만족하는 미수령 건에만 1회씩 발송된다
    And 최대 횟수에 도달한 건은 발송되지 않는다
```

### AC-11-05 자동 재안내 기본값 끔  `정상` `통합`

```gherkin
Scenario: 자동 재안내 기본값 끔
  Given 재안내 설정을 변경한 적이 없다
  When 일일 자동 재안내 작업이 실행된다
  Then 아무 건도 발송되지 않는다
```

### AC-11-06 설정 변경 권한  `권한` `통합`

```gherkin
Scenario: 설정 변경 권한
  Given 직원으로 로그인되어 있다
  When 자동 재안내 설정 변경 API를 요청한다
  Then 403 응답이 반환된다
```

### AC-11-07 대상 조건 재확인  `예외` `통합`

```gherkin
Scenario: 대상 조건 재확인
  Given 재안내 요청 직전에 해당 건이 "출고"되었다
  When 재안내를 요청한다
  Then 발송되지 않고 건너뜀 사유가 반환된다
```
