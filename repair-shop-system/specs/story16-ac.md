## 2. 테스트 전제·데이터

- 공통: 관리자 "owner", 직원 "staff01" 계정, 시험 시각은 한국 시간(KST) 기준으로 고정
- 관리자 "owner", 직원 "staff01", 비활성 직원 "staff00", 임시 비밀번호 직원 "staff02"
- 잠금·자동 로그아웃 기준: 설계 제안값(5회 실패 10분 잠금, 30분 미사용)

## 3. 시나리오 상세 (Given-When-Then)

### AC-16-01 정상 로그인  `정상` `E2E`

```gherkin
Scenario: 정상 로그인
  Given 로그인 화면이다
  When 아이디 "staff01"과 올바른 비밀번호를 입력해 로그인한다
  Then 대시보드로 이동한다
    And 상단에 이름과 "직원"이 표시된다
```

### AC-16-02 실패 문구 통일  `보안` `통합`

```gherkin
Scenario: 실패 문구 통일
  Given 로그인 화면이다
  When 존재하지 않는 아이디로 로그인한다
  Then "아이디 또는 비밀번호가 올바르지 않습니다"가 표시된다
  When 올바른 아이디와 틀린 비밀번호로 로그인한다
  Then 같은 문구가 표시된다
```

### AC-16-03 연속 실패 잠금  `보안` `통합`

```gherkin
Scenario: 연속 실패 잠금
  Given "staff01"이 기준 횟수만큼 연속 로그인에 실패했다
  When 올바른 비밀번호로 로그인한다
  Then 로그인이 거부되고 잠금 안내가 표시된다
  When 잠금 시간이 지난 뒤 올바른 비밀번호로 로그인한다
  Then 로그인된다
```

### AC-16-04 미사용 시 자동 로그아웃  `보안` `E2E`

```gherkin
Scenario: 미사용 시 자동 로그아웃
  Given "staff01"로 로그인되어 있다
  When 기준 시간 동안 아무 조작도 하지 않는다
  Then 자동으로 로그아웃되고 로그인 화면으로 이동한다
```

### AC-16-05 로그아웃 후 화면 노출 없음  `보안` `E2E`

```gherkin
Scenario: 로그아웃 후 화면 노출 없음
  Given 접수 상세 화면을 보고 있다
  When [로그아웃]을 누른 뒤 브라우저 뒤로가기를 누른다
  Then 이전 화면 내용이 표시되지 않고 로그인 화면으로 이동한다
```

### AC-16-06 임시 비밀번호 변경 강제  `보안` `E2E`

```gherkin
Scenario: 임시 비밀번호 변경 강제
  Given "staff02"가 임시 비밀번호를 받았다
  When 임시 비밀번호로 로그인한다
  Then 비밀번호 변경 화면으로 이동한다
  When 변경 없이 접수 목록 주소로 이동한다
  Then 다시 비밀번호 변경 화면으로 돌아온다
```

### AC-16-07 비활성 계정 로그인 불가  `권한` `통합`

```gherkin
Scenario: 비활성 계정 로그인 불가
  Given "staff00"이 비활성 상태다
  When 올바른 비밀번호로 로그인한다
  Then 로그인이 거부된다
```

### AC-16-08 비밀번호 규칙 검증  `입력 검증` `통합`

```gherkin
Scenario: 비밀번호 규칙 검증
  Given 비밀번호 변경 화면이다
  When 규칙에 맞지 않는 비밀번호(예: 숫자만 4자)로 변경한다
  Then 저장되지 않고 규칙 안내가 표시된다
```

### AC-16-09 로그인 기록  `보안` `통합`

```gherkin
Scenario: 로그인 기록
  Given 로그인 성공 1회, 실패 1회가 있었다
  When 로그인 기록을 확인한다
  Then 성공·실패 여부와 일시가 각각 기록되어 있다
    And 비밀번호 원문은 어디에도 기록되지 않는다
```

### AC-16-10 관리자 전용 화면 차단  `권한` `통합`

```gherkin
Scenario: 관리자 전용 화면 차단
  Given 직원으로 로그인되어 있다
  When 매출·설정 화면 주소로 직접 이동한다
  Then 접근이 거부된다
```
