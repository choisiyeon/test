## 3. 시나리오 상세 (Given-When-Then)

### AC-18-01 계정 등록과 임시 비밀번호 1회 표시  `정상` `E2E·통합`

```gherkin
Scenario: 계정 등록과 임시 비밀번호 1회 표시
  Given 관리자로 로그인되어 있다
  When 아이디 "staff03", 이름 "직원C", 역할 "직원"으로 등록한다
  Then 계정이 생성되고 임시 비밀번호가 표시된다
    And 창을 닫으면 임시 비밀번호를 다시 볼 수 없다
    And DB에는 비밀번호가 해시로만 저장된다
```

### AC-18-02 아이디 중복 거부  `입력 검증` `통합`

```gherkin
Scenario: 아이디 중복 거부
  Given "staff01" 계정이 있다
  When 같은 아이디로 등록한다
  Then "이미 사용 중인 아이디입니다"가 표시된다
```

### AC-18-03 비활성화 즉시 적용  `보안` `E2E`

```gherkin
Scenario: 비활성화 즉시 적용
  Given "staff01"이 다른 기기에서 로그인 중이다
  When 관리자가 "staff01"을 비활성화한다
  Then "staff01"의 다음 요청부터 로그인 화면으로 이동한다
    And 이후 로그인할 수 없다
```

### AC-18-04 비활성 계정의 과거 기록 유지  `정상` `E2E`

```gherkin
Scenario: 비활성 계정의 과거 기록 유지
  Given 비활성화된 "staff01"이 등록한 접수가 있다
  When 해당 접수 상세를 연다
  Then 등록자 이름이 그대로 표시된다
```

### AC-18-05 비밀번호 초기화  `정상` `통합`

```gherkin
Scenario: 비밀번호 초기화
  Given "staff01"이 활성 상태다
  When 관리자가 [비밀번호 초기화]를 누른다
  Then 새 임시 비밀번호가 1회 표시된다
    And 기존 비밀번호로는 로그인할 수 없다
    And 새 임시 비밀번호로 로그인하면 비밀번호 변경 화면으로 이동한다
```

### AC-18-06 마지막 관리자 보호  `예외` `통합`

```gherkin
Scenario: 마지막 관리자 보호
  Given 관리자 계정이 "owner" 1개뿐이다
  When "owner"를 비활성화하거나 역할을 "직원"으로 바꾼다
  Then 거부되고 마지막 관리자 안내가 표시된다
```

### AC-18-07 직원 접근 차단  `권한` `E2E·통합`

```gherkin
Scenario: 직원 접근 차단
  Given 직원으로 로그인되어 있다
  When 직원 계정 화면이나 계정 API에 접근한다
  Then 메뉴가 보이지 않고 API는 403 응답을 반환한다
```

### AC-18-08 재활성화  `정상` `통합`

```gherkin
Scenario: 재활성화
  Given "staff01"이 비활성 상태다
  When 관리자가 [재활성화]를 누른다
  Then "staff01"이 다시 로그인할 수 있다
```

### AC-18-09 계정 작업 기록  `보안` `통합`

```gherkin
Scenario: 계정 작업 기록
  Given 관리자가 등록·비활성화·초기화를 했다
  When 작업 기록을 확인한다
  Then 각 작업의 종류, 대상, 처리자, 일시가 남아 있다
    And 임시 비밀번호는 기록에 포함되지 않는다
```
