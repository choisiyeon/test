## 3. 시나리오 상세 (Given-When-Then)

### AC-13-01 관리자의 결제 취소  `정상` `E2E`

```gherkin
Scenario: 관리자의 결제 취소
  Given 관리자로 로그인되어 있다
  When 접수 G 결제 내역에서 [결제 취소]를 누르고 사유 "결제수단 오기록"을 입력해 확인한다
  Then 결제가 "취소"로 표시된다
```

### AC-13-02 취소 정보 표시  `정상` `E2E`

```gherkin
Scenario: 취소 정보 표시
  Given 접수 G의 결제가 취소되었다
  When 접수 상세를 연다
  Then 원래 결제가 취소선으로 표시되고 취소 일시, 사유, 처리자가 함께 표시된다
```

### AC-13-03 직원 취소 차단  `권한` `E2E·통합`

```gherkin
Scenario: 직원 취소 차단
  Given 직원으로 로그인되어 있다
  When 접수 상세를 연다
  Then [결제 취소] 버튼이 보이지 않는다
  When 결제 취소 API를 요청한다
  Then 403 응답이 반환된다
```

### AC-13-04 취소 후 재결제  `정상` `통합`

```gherkin
Scenario: 취소 후 재결제
  Given 접수 G의 결제가 취소되었다
  When 결제수단 "카드"로 다시 결제를 기록한다
  Then 새 결제가 저장되고 접수는 "결제 완료"로 표시된다
```

### AC-13-05 취소일 기준 매출 차감  `정상` `통합`

```gherkin
Scenario: 취소일 기준 매출 차감
  Given 11-24에 결제, 11-25에 취소되었다
  When 11월 일별 매출을 조회한다
  Then 11-24 총매출에 8000원, 11-25 취소액에 8000원이 반영된다
```

### AC-13-06 중복 취소 불가  `예외` `통합`

```gherkin
Scenario: 중복 취소 불가
  Given 이미 취소된 결제다
  When 다시 취소를 요청한다
  Then 거부되고 "이미 취소된 결제입니다" 안내가 반환된다
```

### AC-13-07 결제 기록 물리 삭제 없음  `보안` `통합`

```gherkin
Scenario: 결제 기록 물리 삭제 없음
  Given 결제를 취소했다
  When 결제 데이터를 조회한다
  Then 원래 결제 기록이 취소 표시와 함께 남아 있다
```

### AC-13-08 사유 누락 거부  `입력 검증` `통합`

```gherkin
Scenario: 사유 누락 거부
  Given 관리자로 로그인되어 있다
  When 사유 없이 결제 취소를 요청한다
  Then 취소되지 않는다
```
