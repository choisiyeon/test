# [US-11] 미수령 재안내 발송 — 개발 Task 설계서

| 항목 | 내용 |
| --- | --- |
| 에픽 | E3 완료 알림 |
| 스토리 | 직원으로서 오래 찾아가지 않은 고객에게 수령 안내를 다시 보내고 싶다. 장기 미수령 의류를 줄이고 보관 공간을 확보하기 위해서다. |
| 우선순위 / 릴리스 | 선택 / 2차 |
| 관련 기능 | F-13 미수령 재안내 |
| 관련 화면 / 데이터 | S-05 고객 관리(미수령 탭) / D-04 알림 이력, D-08 매장 설정 |
| 선행 작업 | US-08(미수령 목록), US-09(발송 서비스), US-10 |
| 작성일 | 2026-11-25 |

---

## 1. 요약

- 미수령 목록(US-08)에서 건별 또는 여러 건 선택 후 재안내 발송(수동)
- 자동 재안내(완료 후 일정 일수 경과 시 자동 발송)는 설정으로 켜고 끌 수 있게 설계, 기본값은 '끔'
- 재안내 문구는 완료 안내와 별도 문구 사용(US-20)
- 같은 건에 짧은 간격으로 반복 발송되지 않도록 최소 간격 제한

---

## 2. 인수 조건

1. 미수령 목록에서 [재안내]를 누르고 확인하면 해당 고객에게 재안내가 발송되고 이력에 '재안내'로 기록된다.
2. 여러 건을 선택해 [선택 건 재안내]를 누르면 선택한 건마다 발송되고, 성공·실패 건수가 표시된다.
3. 마지막 발송 후 최소 간격이 지나지 않은 건은 재안내 버튼이 비활성화되고 사유("n일 후 가능")가 표시된다.
4. 자동 재안내가 켜져 있으면 기준 일수가 지난 미수령 건에 하루 1회 자동 발송된다(같은 건 최대 횟수 제한).
5. 자동 재안내 설정은 관리자만 변경할 수 있다.

---

## 3. 데이터 모델 변경

- NotificationLog `type = REMIND` 사용(US-09 정의)
- StoreSetting 키 추가

| 키 | 의미 | 기본값 |
| --- | --- | --- |
| `REMIND_AUTO_ENABLED` | 자동 재안내 사용 | `false` |
| `REMIND_MIN_INTERVAL_DAYS` | 같은 건 재안내 최소 간격(일) | 결정 필요 |
| `REMIND_MAX_COUNT` | 같은 건 자동 재안내 최대 횟수 | 결정 필요 |

---

## 4. API 설계

| 메서드 | 경로 | 설명 | 권한 |
| --- | --- | --- | --- |
| POST | `/api/orders/remind` | 재안내 발송(접수 id 목록) | 관리자·직원 |
| GET/PUT | `/api/settings/REMIND_*` | 재안내 설정 조회·변경 | 조회: 전원 / 변경: 관리자 |

```json
// 요청
{ "orderIds": ["ck1...", "ck2..."] }
// 응답 200
{ "success": 1, "failed": 0, "skipped": [{ "orderId": "ck2...", "reason": "MIN_INTERVAL", "availableAt": "2026-11-28" }] }
```

### 처리 규칙

- 대상 조건 재확인: 상태 '완료' + 미수령 기준 일수 경과 + 최소 간격 경과 + 고객 번호 존재
- 1회 요청 최대 건수 제한(예: 50건, 제안값)
- 자동 재안내: 작업자(US-09 worker)에 매일 정해진 시각 실행 작업 추가(실행 시각은 결정 필요), `REMIND_MAX_COUNT` 초과 건 제외
